# V4 API Error Contract

## Purpose

All `/api/v1` endpoints should return a consistent JSON shape for application-level errors.

## Error Shape

```json
{
  "detail": "Human readable error message",
  "error_code": "machine_readable_error_code"
}
```

Frontend behavior:

```text
Display detail to users.
Use error_code for routing, state recovery, or specialized UI handling.
```

## Recommended Error Codes

```text
profile_session_not_found
invalid_profile_session_state
resume_empty
resume_file_empty
resume_file_unsupported_type
resume_file_too_large
resume_text_too_long
resume_document_not_found
parsed_review_not_found
profile_draft_not_found
confirmed_profile_not_found
confirmed_profile_required
job_search_run_not_found
brief_not_found
llm_provider_unavailable
```

## Implementation Notes

FastAPI route handlers should prefer explicit `error_code` values over free-form strings when rejecting known product states.

Validation errors generated by framework-level request parsing may keep FastAPI's default shape until a dedicated validation wrapper is introduced, but product-flow validation should use this contract.
