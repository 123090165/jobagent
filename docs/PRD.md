# JobAgent PRD

> 用途：定义 JobAgent 是什么、做什么、不做什么，以及 v0.1 的验收边界。

## 1. 项目背景

求职者在准备 AI Agent、LLM 应用开发、Python 后端等岗位时，经常遇到这些问题：

- 不清楚目标岗位真正看重哪些能力。
- 不知道自己的简历和 JD 差在哪里。
- 项目经历写得像流水账，缺少岗位相关性。
- 项目经不起技术面试的深入追问。
- 投递、复盘、补强计划缺少系统记录。

JobAgent 希望把“看岗位、改简历、准备面试、复盘投递”组织成一个可持续迭代的求职工作台。

## 2. 目标用户

- 正在投递 AI、Agent、LLM 应用、Python 后端、数据应用相关岗位的求职者。
- 需要把课程项目、毕业设计或个人项目包装成可展示经历的学生。
- 希望用结构化方式持续管理简历版本、岗位 JD 和面试准备材料的人。

## 3. 用户痛点

- JD 信息量大，但难以提取关键能力要求。
- 简历和 JD 的匹配关系不明确。
- 简历优化容易空泛，甚至容易被 AI 编造经历。
- 项目经历缺少可被追问、可被证明的技术细节。
- 缺少从单次分析到长期求职计划的闭环。

## 4. 项目目标

构建一个面向求职者的多智能体求职工作台，逐步支持：

- 用户画像构建。
- 岗位 JD 搜集与入库。
- JD 结构化分析。
- 简历解析。
- 简历与 JD 匹配度分析。
- 简历优化建议生成。
- 项目追问问题生成。
- 模拟面试与求职计划管理。

## 5. MVP 范围

v0.1 只做最小闭环：

- 用户输入或粘贴简历文本。
- 用户粘贴目标岗位 JD。
- 系统解析简历和 JD。
- 系统输出匹配度报告。
- 系统输出简历优化建议。
- 系统输出项目追问问题。
- 系统生成 Markdown 报告。

第一版的核心路径是：

```text
简历文本 + JD 文本 -> 匹配报告 + 简历优化建议 + 项目追问问题 + Markdown 报告
```

## 6. 非 MVP 范围

第一阶段不做：

- 自动投递。
- 自动登录招聘网站。
- 验证码处理。
- 大规模爬虫。
- 多用户权限系统。
- 商业级推荐算法。
- 复杂岗位搜索和实时抓取。
- RAG、MCP、LangGraph 的完整实现。

## 7. 核心用户流程

1. 用户填写或粘贴求职目标。
2. 用户输入简历文本。
3. 用户粘贴目标岗位 JD。
4. 系统解析简历和 JD，并生成结构化结果。
5. 系统进行匹配度分析。
6. 系统给出简历优化建议。
7. 系统生成项目追问问题。
8. 系统生成 Markdown 报告。
9. 用户保存报告，并据此修改简历和准备面试。

## 8. 验收标准

- 端到端流程可以运行。
- 输入简历和 JD 后，能得到完整 Markdown 报告。
- 输出包含结构化 JD 分析、简历分析、匹配度、优势、短板、优化建议和项目追问。
- 简历优化不编造用户没有提供的经历、公司、项目、数据或技术栈。
- 匹配分和建议有可解释依据。
- 项目追问具体，能暴露真实技术短板。
- 项目结构清晰，方便后续接入 LLM、FastAPI、SQLite、LangGraph、RAG 和 MCP。
